# 独立项目与执行服务的集成合同草案

## 职责划分

- 纬舟：桌面交互、产品对象、品牌、用户决策和交付检查。
- 执行服务：管理真实 CLI 子进程、模型调用、技能与工具、代码工作目录、协作派发、审批守卫和事件持久化。
- 飞书：作为消息、通知与快捷处理渠道，映射同一个项目/任务/Run/请求，不作为唯一主键来源。

当前仓库保留无依赖原型，不引入或复制执行服务的后台配置。实际接入前需决定由哪个服务持有业务数据的唯一写入权，避免界面和执行端各自存一份不可对账的任务状态。

## 数据与标识

独立内部 ID：workspaceId、projectId、requirementId、taskId、runId、roleId、approvalId、artifactId。飞书应用/会话/话题 ID 仅保留为渠道关联。

Run 固定角色版本、模型配置引用与有效值、技能来源/ref、权限策略、需求与计划版本、Git remote/基准提交/工作分支/目录。凭据仅保留引用，不进入快照和导出。

## 服务动作

以下是待实现合同，不是目前可调用的接口：

| 领域 | 动作 | 服务端必须保证 |
| --- | --- | --- |
| 角色 | 保存草稿、检查、试运行、启用、停用 | 版本检查、兼容性、权限边界、运行中配置不被改写 |
| 飞书 | 开始授权、取消、状态、检测、解绑 | 用户授权、到期处理、凭据安全、应用归属与路由 |
| 项目 | 绑定仓库、读取状态、准备隔离目录 | 不覆盖本地改动，不盲目切换运行任务的分支 |
| 任务 | 创建、排队、开始、停止、重试 | 幂等请求；每次执行独立 Run；并发与依赖检查 |
| 人工请求 | 澄清答案、方案确认、操作决定 | 归属与操作者校验；过期、重复与旧版本决定失效 |
| 交付 | 提交版本、获取证据、验收、退回 | 关联准确的 Run 和需求版本，历史不可被覆盖 |

## 事件与恢复

推荐本机受保护的应用接口加可恢复事件流。先取状态快照，再从游标订阅后续事件。每个事件包含 eventId、sequence、taskId、runId、occurredAt、type、payloadVersion、payload。

重复事件按 ID 去重；乱序按 sequence 处理；断线以最近游标补齐；无法补齐时重取状态快照。界面只在确认成功后变更最终状态，异步请求可以显示处理中。

停止请求先显示“正在停止”，执行服务确认进程结束才显示“已停止”。心跳丢失显示状态待确认，不推断进程已经死亡。前端关闭不应意外终止后台任务，真正退出时展示影响并遵循用户选择。

## 本机接口边界

接口认证与本机调用来源校验、事件流授权、路径限制、命令参数校验由正式服务实现。不能把监听 localhost 当成完全没有调用边界。模型与飞书密钥从系统凭据存储读取，不下发到浏览器存储。

## 原型实现说明

当前浏览器存储只保存模拟角色、任务、Run 和草稿，版本号为 2；不保存真实凭据。原型的服务端仅负责静态文件预览，不实现此合同中的执行动作。
