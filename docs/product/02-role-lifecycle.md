# 角色创建与生命周期

## 核心原则

角色是一位可配置的 AI 成员，包含职责、CLI、模型、Skills、权限和渠道连接。首版不要求用户先理解模板和实例的两层区别；支持复制角色，后续再抽取模板。

角色就绪、CLI 可用、模型连通和飞书已连接是不同维度。飞书可选；离线的模型或缺失的依赖会阻止新任务执行。

## 六步创建

| 步骤 | 必填内容与交互 | 成功标准 | 失败或退出时 |
| --- | --- | --- | --- |
| 1 基本信息 | 名称、唯一标识、职责、输入与交付要求 | 标识格式与唯一性通过；职责明确 | 暂存草稿，显示缺少内容 |
| 2 CLI / 模型 | 选择 CLI、引用兼容的模型配置；分别检测版本、登录、模型连接 | 所有执行所需检查通过 | 显示具体失败项，保留表单，不让统一的在线徽章掩盖问题 |
| 3 Skills | 选择已安装技能；可进入市场安装并返回 | 来源与版本固定、依赖与 CLI 兼容性通过 | 不丢失角色草稿；区分下载失败、依赖缺失和外部账号未授权 |
| 4 权限边界 | 只读建议 / 项目内受控执行；文件范围、最大并发 | 可解释的最小执行范围 | 不提供含糊的永久全权限开关 |
| 5 飞书连接 | 新建机器人 / 关联已有应用 / 暂不接入 | 用户授权后，分别检查能力、权限、事件、连接与发布可用性 | 支持拒绝、过期、检测失败、取消与重新开始 |
| 6 试运行 | 汇总配置；受控测试输入；查看输出、耗时和调用证据 | 环境与试运行通过后允许启用 | 可重试、返回修改或保存草稿；失败不伪装为已就绪 |

原型将上述检测与试运行明确标记为模拟。实际 CLI 和飞书 SDK 调用由后续服务集成完成。

## 生命周期

草稿 → 配置中 → 就绪 → 已停用。异常健康状态附着在就绪角色上，不用删除角色来表示离线。

- 草稿：可以继续编辑，不参与分配和队列调度。
- 就绪：可以接收任务，但每次启动仍做执行前检查。
- 已停用：停止接收新任务；是否停止正在运行的任务由用户单独决定。
- 健康异常：说明具体不可用能力；恢复健康后重新检查，不隐式改变职责和模型。

## 修改与版本

- 保存角色配置生成版本号；开始执行时固定版本和有效配置，不在任务中途热切换模型。
- 修改职责、CLI、模型或 Skills 后，标记需要重新检测；已运行的 Run 保留原配置。
- 重命名只影响展示；标识应稳定。角色被项目、团队或任务引用时，删除前先迁移依赖或归档。
- 删除、停用、断开飞书是三个独立动作。断开渠道不删除任务历史，也不撤销用户在飞书中创建的应用。

## 飞书细节

目标体验：预填名称与描述 → 平台返回授权地址 → 用户扫码选择新建或已有应用 → 取得凭据并安全保存 → 检测 → 绑定角色。

飞书 SDK 的 `registerApp` 支持授权创建与更新已有应用，但不等价于无需授权读取整个开发者控制台。开发集成时核对租户能力、必要 scopes、事件订阅和发布条件。

首版建议一个应用机器人关联一个可见角色；执行层可复用凭据连接，但展示名称、权限和消息路由需清楚区分。一个应用供多个角色复用时，必须显式设计成员选择与路由，不能让同一条消息被多个角色同时领取。

## 权限与授权

只读建议仍会受工具权限与文件读取范围限制。受控执行只允许在当前项目的工作范围内操作。远程推送、部署、删除数据和扩大授权等操作，绑定本次 Run、动作参数与用户决定。

试运行只确认配置可用，不构成后续敏感操作的永久许可。外部账号连接与技能本身安装也需分别展示。

## 验收要点

1. 切换 CLI 后只显示该引擎兼容的模型与参数。
2. 从技能市场返回后保留职责、模型和已选技能。
3. 授权拒绝或过期不会清空角色表单，可以重新开始。
4. 草稿和未通过试运行的角色不会接收执行任务。
5. 修改角色后，历史 Run 中的模型、技能和权限快照保持原样。
