# Agent Team 桌面端产品方案 v1

日期：2026-10-22。阶段：产品设计 / 可点击原型。范围：个人或小团队负责人指挥 AI 团队完成项目交付。

## 已确认需求

1. 桌面应用驱动现有 Agent-Team 能力，保留飞书入口。
2. 角色可配置职责、Skills、CLI 与模型；支持后续修改。
3. 技能中心包括已安装与技能市场，可搜索、查看、安装后绑定角色。
4. 项目管理展示 Git 地址、默认分支、当前分支及工作目录。
5. 独立任务管理页面；每条任务必须绑定一个项目。
6. 任务明确展示是否开始、当前步骤、已完成步骤、是否完成及异常情况。
7. 创建角色时可联动飞书创建或关联机器人。
8. 包含团队管理、需求管理、模型设置。
9. 使用 Superdesign 的自主编写 HTML 导入方式；不调用付费生成或消耗设计积分。

## 产品对象与关系

- 项目：目标、代码仓库、分支、工作目录、默认团队与共享上下文。
- 需求：归属项目，记录问题、范围、验收标准、澄清和方案版本。
- 任务：必须归属项目，可关联需求；包含负责人、执行步骤、依赖、验收标准。
- 执行记录（Run）：每次执行/重试单独留档，固化 CLI、模型配置版本、Skill 版本与 Git 分支/基准提交。
- 交付物：归属任务和执行记录，可为方案、代码差异、测试报告或链接；有待验收/通过/退回状态。
- 角色：首版作为可配置的 AI 执行成员，包含名称、职责提示、CLI、模型配置引用、Skill 绑定、飞书连接。暂不增加独立模板/实例两层表单；后续可从角色另存模板。
- 团队：成员、负责人、默认协作顺序和并发规则；项目绑定团队。
- 技能：安装资源；被多个角色引用，安装与角色启用分开处理。
- 模型配置：CLI 对应的供应商/端点/凭证引用、模型和推理设置，可被多个角色复用。

## 页面与核心交互

| 页面 | 核心内容 | 原型覆盖 |
| --- | --- | --- |
| 工作台 | 待我处理、执行概览、项目入口、近期交付 | 浏览并进入任务 |
| 项目 | Git URL、默认/当前分支、目录、团队、任务进度 | 查看详情、按项目筛选任务、新建演示项目 |
| 任务 | 全局列表/看板、项目与状态筛选、关键词搜索 | 新建、查看、开始、推进演示步骤、停止、重试、验收 |
| 需求 | 目标、优先级、阶段、验收标准、关联任务 | 查看需求、创建演示需求、转为项目任务 |
| 角色 | 名称/职责、CLI、模型、已绑定 Skills、飞书状态 | 查看/编辑；四步创建；跳转市场并保留表单 |
| 团队 | 负责人、成员及默认流程 | 浏览、创建演示团队 |
| 技能 | 市场与已安装；来源、版本标识、CLI 兼容性 | 搜索、查看、模拟安装、返回角色继续配置 |
| 设置 | 模型配置、CLI 状态、飞书连接、通知 | 保存演示模型配置；不输入或存储真实密钥 |

## 任务状态与进度

主状态：未开始 → 执行中 → 待验收 → 已完成。分支状态：待处理、失败、已停止。

- 未开始：没有执行开始时间；进度 0/N。
- 执行中：显示当前步骤、已完成步骤、开始时间、最新事件与负责人。
- 待处理：展示明确原因（需求澄清/方案确认/操作审批/依赖等待），不假装仍在执行。
- 待验收：执行结束且交付物就绪，验收前不显示已完成。
- 已完成：验收通过，记录通过时间；已完成 N/N。
- 失败：保留失败步骤与错误，允许发起新的执行记录重试。
- 已停止：终止当前执行；重新执行创建新 Run，不声称精确断点续跑。
- 进度基于显式步骤完成数：例如 2/5，附“按步骤统计”，不代表工作量或剩余时间预测。步骤不可确定时显示阶段与事件，不伪造百分比。
- 项目进度为已验收任务数 / 总任务数，单独显示执行中、阻塞和待验收数。

## 创建角色与飞书联动

四步：基本信息 → CLI 与模型 → Skills → 飞书连接。

飞书连接包含“新建飞书机器人”“关联已有应用”“暂不接入”三个入口。角色创建可先保存草稿；飞书连接失败不会丢失角色表单。

正式流程：预填应用名称/描述 → 展示平台返回的授权链接及二维码 → 用户在飞书中确认新建或选择已有应用 → 回传应用凭据 → 绑定角色 → 分别检测机器人能力、必要权限、事件/回调、发布/可用状态和长连接。

核验依据：当前安装的 `@larksuiteoapi/node-sdk` README.zh.md 的“一键创建应用”部分明确提供 `registerApp`、`appPreset`、`addons`、`createOnly` 与 `appId`。因此可以实现用户扫码授权的新建/关联体验，无需把用户强制引导到控制台手工抄配置。不能据此声称可无授权枚举控制台全部应用，也不能把返回凭据等同于连接和权限全部就绪。

参考：[飞书官方 Node SDK](https://github.com/larksuite/node-sdk)、[飞书开发者后台](https://open.feishu.cn/app)。生产实现应在集成时再次核对 SDK 合同和租户可用性。

授权状态：待授权、授权中、已授权待检测、已连接、授权拒绝、已过期、连接异常。轮询可取消并支持重新开始；凭据交给系统密钥存储，日志与 UI 不展示明文。原型只模拟授权过程，不产生真实应用或二维码。

## Git 与项目

- 项目列表：仓库地址摘要、当前分支、默认分支、任务完成数、团队。
- 项目详情：完整远程地址、remote 名称、默认分支、当前分支、工作目录、仓库状态与最后检查时间。
- 任务详情：执行分支、基准提交、工作目录；后续支持独立 worktree。
- 切换分支属于执行环境变更，应检查运行任务与未提交改动；原型不执行切换。
- 首版一个项目一个主仓库。多仓库项目留给后续版本。
- 演示数据采用 example.invalid 域名，不暗示已经读取真实仓库或远程状态。

## 技能市场与角色引用

正式安装流程：搜索市场/输入仓库地址 → 查看来源与说明、版本/ref、依赖与 CLI 兼容性 → 选择安装范围 → 安装与依赖检查 → 绑定角色。

状态应包含未安装、安装中、已安装、依赖缺失、不兼容与安装失败。安装成功不等于第三方账号已经授权；按技能要求独立提示。角色配置修改对后续执行生效，运行记录保留原有版本。

原型中市场条目是示例，安装仅变更内存；刷新即重置。正式版再连接真实市场索引与安装器，不展示虚构下载量、评分或版本发布信息。

## 风格与设计约束

纸白背景、森林绿主色、细分隔线、适度紧凑的工作台。首要内容为任务和决策，减少装饰。主导航：工作台、项目管理、任务管理、需求管理、角色管理、团队管理、技能中心、设置。

列表和看板共享同一数据。状态用文字+图标+颜色。任务详情在右侧展开；角色和新建表单使用模态窗口。所有主要操作支持键盘焦点，Escape 关闭临时面板。

## 首版范围与边界

首版闭环：配置模型 → 安装 Skills → 创建角色并关联飞书 → 组建团队 → 关联项目与仓库 → 提交需求 → 创建任务 → 执行 → 验收。

现有运行时已有会话、协作、审批、澄清、定时调度、模型配置等能力；桌面产品仍需补建独立的项目/需求/任务/Run 数据模型、应用服务接口及可靠事件推送。不能把当前飞书话题状态直接当成全部业务状态。

本交付是产品说明和交互演示，不连接真实 CLI、Git、技能安装器或飞书授权服务，不处理真实密钥。后续再依据审阅结果实现桌面壳和后端接线。
