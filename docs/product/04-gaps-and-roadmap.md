# 产品遗漏、优先级与版本范围

第一版已有模块入口，但首个可用版本需要补齐运行边界、异常恢复和验收闭环。下表区分“原型可以演示”与“真实服务已实现”；前者不能替代后者。

## 首版必须解决 P0

| 遗漏 | 用户会遇到的问题 | 产品决策与验收标准 | 本轮覆盖 |
| --- | --- | --- | --- |
| 首次启动与执行服务检测 | 装好应用却不知道还缺 CLI、登录还是模型 | 引导选择项目目录；分别检测 CLI/账号/模型/技能/服务，失败可定位与重试 | 角色检测原型；完整首次启动待设计 |
| 角色生命周期 | 半成品角色被分配任务 | 草稿、就绪、停用分开；检测和试运行后启用 | 六步原型与草稿恢复 |
| 任务与执行记录 | 重试覆盖历史，无法追溯配置 | 独立 Run 与不可回写的配置、计划、代码基线快照 | Run 历史演示 |
| 执行检查与代码隔离 | 多角色互相覆盖代码，未提交改动丢失 | 检查 Git 状态；独立分支/目录；明确冲突和共享目录风险 | 检查和隔离方式原型；真实 Git 待接入 |
| 统一人工处理 | 飞书和桌面分别审批、重复放行 | 统一待处理对象；请求版本、操作者、有效期、幂等决定 | 任务内审批演示；跨渠道同步待实现 |
| 验收与证据 | 模型说完成，用户却没有可验证结果 | 交付版本、代码差异、验证记录与逐项验收；允许退回 | 原型验收与退回 |
| 服务断线与进程恢复 | 前端显示停止但后台还运行，重连后重复执行 | 前端状态过期提示；服务确认旧进程；恢复与重试分开 | 中断状态演示；进程核对待实现 |
| 凭据与权限范围 | 密钥混入导出、日志；角色可访问过大目录 | 系统密钥存储，脱敏日志；项目范围授权；独立敏感动作审批 | 权限配置原型；正式执行策略待实现 |
| 持久化与迁移 | 重启丢失任务、配置格式升级损坏 | 原子写入与版本迁移；备份恢复；保留最后有效数据 | 浏览器演示持久化；正式存储待实现 |
| 对外动作与重复执行 | 重试再次推送、发布或创建资源 | 记录动作结果与幂等键；失败分类；不盲目重放副作用 | 文档与审批原型；执行保障待实现 |

## 随后完善 P1

| 能力 | 需要明确的设计 |
| --- | --- |
| 需求版本与变更影响 | 需求、方案、验收标准各自版本；变更时提示哪些任务需要重审 |
| 任务依赖与队列 | 防止依赖循环；优先级、公平性、并发名额和等待原因；团队任务关系 |
| 预算与时限 | 模型用量上报、任务/项目额度、超时与重试上限；费用区分实测、估算与未知 |
| 技能供应与升级 | 真实市场来源、版本固定、依赖安装、兼容性、更新差异和回退；外部账号授权独立 |
| 角色配置回滚 | 配置版本比较、复制、停用、归档和依赖迁移；禁止删除后丢失历史身份 |
| 模型故障转移 | 展示为什么切换、切到了哪里；副作用发生后的转移边界；能力与推理参数兼容 |
| 通知、托盘与后台 | 关闭窗口和真正退出分开；操作系统通知定位到具体任务；勿扰和离线状态 |
| 数据导出与诊断包 | 只导出必要信息、自动脱敏、保留期限；用户能检查诊断内容再分享 |
| 全局搜索与快捷操作 | 项目、任务、需求、产物统一检索；键盘导航、筛选保存与常用项目 |
| 应用更新与服务兼容 | 版本兼容检查、升级失败恢复、迁移前备份，避免新界面操作旧执行服务 |

## 后续 P2

多人协作与人员权限、组织空间、多机器执行、云端同步、多仓库项目、工作流可视化编辑、团队模板市场、质量评估与模型对比。

这些能力扩展产品范围，首版不通过大量空导航占位。预留数据关系和服务合同即可。

## 首版验收目标

用户能在新设备上完成环境检查，创建可用角色，绑定项目与 Git 仓库，提交一条带验收标准的任务；可以看到真实执行进展、处理一次审批、检查交付并验收。一次失败重试保留旧 Run，关闭并重开应用能恢复状态，飞书和桌面不会重复执行同一决定。

只有上述链路连接真实执行服务并通过验证后，才标记为可用桌面产品。当前仓库处于产品设计与交互原型阶段。
