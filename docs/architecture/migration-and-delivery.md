# 内核封装、交付阶段与跨设备开发 v0.2

方向已确认：打包 Agent-Team 作为纬舟内核，必要时同步修改 Agent-Team。正式开发在另一台设备进行；本轮只更新方案与规范。

## 1. 从迁移源码调整为封装既有内核

2026-10-22 已授权按 M0—M4 正式开发，并在每阶段验收后连续推进。当前实现、验证和关联提交见 [开发交接](../development/progress.md)。本文件保留各阶段退出条件，设计会话的“不实现”限制已被新授权取代。

[Agent-Team](https://github.com/CerrorJ/Agent-Team) 持续作为内核唯一源码仓库。原方案中“迁移到纬舟”的措辞被本版替代：能力在 Agent-Team 中解耦、复用、补充和打包；纬舟消费产物，不复制业务代码。

| 现有位置                                 | 在 Agent-Team 中的演进                         | 纬舟消费内容                 |
| ---------------------------------------- | ---------------------------------------------- | ---------------------------- |
| `src/cli/types.ts`、Claude/Codex adapter | 继续维护解析和能力矩阵，输出归一化事件         | 版本化 CLI 能力与执行事件    |
| runner、spawn-cli、timeout               | 抽出可被嵌入式入口调用的执行能力，完善平台验证 | 开始、停止、错误、进度       |
| provider-error 与恢复策略                | 保留错误归一化，完善持久状态和恢复边界         | 错误码、可用动作、脱敏原因   |
| workspace 与 Git                         | 增量支持项目、Run、worktree 和锁               | 仓库/分支/目录状态及预检结果 |
| 审批、澄清、方案流程                     | 解耦飞书 ID，形成统一用例与持久请求            | 人工请求、版本化决定和结果   |
| JSON store                               | 保持旧入口兼容，增量实现内核仓储与可验证迁移   | 查询快照与游标，不暴露数据库 |
| `src/im/lark.ts` 与卡片处理              | 保留为同一内核的飞书渠道                       | 绑定、连接状态和跨渠道事件   |
| MCP 工具服务                             | 工具绑定 Run 与权限，调用共享用例              | 对应业务状态和产物           |
| `src/index.ts`、`src/app/runtime.ts`     | 分离内核创建、飞书入口和嵌入式入口             | 可独立启动/停止的打包内核    |

项目/需求/角色版本/完整任务模型等缺失能力也在 Agent-Team 实现，不在桌面仓库补一套执行内核。桌面只实现业务交互、宿主和客户端投影。

保留旧入口与回归测试。联调使用独立测试数据与飞书应用，禁止新旧入口双重消费同一事件或写同一工作区。不复制生产 `.env`、CLI 登录状态、会话、真实聊天和运行目录。

## 3. 关键验证

- 打包后的纬舟可启动锁定内核，不依赖相邻 Agent-Team 源码、开发 node_modules 或本机 Node。
- 原独立飞书服务入口兼容；嵌入模式无飞书配置可用，配置后两渠道操作同一对象。
- 关闭窗口持续执行；完全退出停止并确认进程；启动窗口崩溃后不重复执行未知动作。
- 脏文件、分支冲突、中文/空格路径不破坏用户文件；进程停止与凭据在两平台原生验证。
- 重复审批、过期卡片、乱序/重复事件、断线游标、日志洪水和未知状态均有明确结果。
- 内核协议或数据版本不兼容时明确阻塞；备份恢复可用，不默认回退旧数据库 schema。
- Agent-Team 与纬舟分别运行适用检查，再做两仓协议、打包集成与真实闭环验证。

## 4. 新设备 Codex 交接

1. 同时克隆纬舟和 Agent-Team，读取各自 AGENTS.md；原服务从 OpenWiki 入口理解行为，生成页不手动修改。
2. 读取确认表和内核集成方案，识别已确认方向与尚需技术验证的细节，不再次询问用户已确认的 1–4 项。
3. 用户已授权必要时同步修改 Agent-Team。正常内核接口、协议、持久化、平台兼容、测试和打包改造在授权内；不因此自行切换生产服务。
4. 工程依赖、CLI 和凭据在新设备单独准备，不复制设计设备缓存和登录文件；先保护各仓已有改动。
5. 本地可用明确开发引用联调，但发行锁定已提交版本/产物；先内核后桌面，两仓分别提交和验证并记录关联。
6. 产品交互参考另克隆的 `product-design`，不整体合并原型。分支不带 `codex/`。

可直接交给开发设备的说明：

> 请先读两仓 AGENTS.md、纬舟 README、review.md、kernel-integration.md 和开发规范。已确认 Electron/React/TypeScript、单所有者本机执行、关闭窗口继续/完全退出停止、首版 macOS/Windows；Agent-Team 打包作为唯一内核，纬舟不重写内核，需要时可以同步修改 Agent-Team。按当前开发指令从 M0 开始，保留原飞书入口；共享业务与协议在 Agent-Team 完成，纬舟锁定产物并实现宿主/客户端/页面。添加必要中文注释，遵守单一职责、原子性、可读性和文件规模约束。分别提交与测试，记录关联版本，不操作生产配置或复制凭据。
