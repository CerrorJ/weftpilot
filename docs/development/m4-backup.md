# M4 工作台备份与恢复

承接桌面 `426bac4`，内核固定 `0.5.7 / daea984f3d7b5ee6d2103d08a6b628dfc0339bf3 / protocol1 / schema7`。
Windows独立Tester与Reviewer均通过0.5.7备份增量；本记录不代表M4整体验收或macOS通过。

## 已实现范围

内核独占读取一致SQLite快照，备份业务历史、交付文本/补丁、已安装与历史技能、待确认的技能预览。
不包含项目仓库、执行worktree、系统凭据或CLI登录；不能替代代码备份，新设备需重新授权项目目录和凭据。
所有Run、人工等待和技能安装必须结束；进程待确认先核对，不能通过恢复绕过。

桌面只通过系统目录选择器选位置；渲染层没有任意文件访问或数据库连接。
恢复前展示时间、版本、对象数量及范围，必须勾选确认。15分钟预览票据绑定清单摘要，选择后内容变化拒绝。
内核仅恢复到新目录，核对文件集合、摘要、数据库、运行时对象和技能内容，准备成功后冻结所有渠道写用例。
宿主确认旧内核结束，启动新内核、验证锁定提交，再原子替换`active-kernel.json`槽位。
旧库和项目始终保留；握手或指针失败尝试重新打开旧库，无法确认的切换记录uncertain，不自动重放。
切换与完全退出共用Promise互斥；退出等待切换收敛后停止实际生效的内核。

停机结果投递与工具进程退出可能乱序。0.5.5新宿主请求`acknowledgeExit`，收到并验证stopped后发送绑定requestId的`shutdown-ack`，工具进程再退出；未收讫30秒后非零退出。宿主仍须同时核对OS退出，不把ACK当作进程结束证据。旧无ACK宿主及独立飞书入口保持兼容。

## 复现

```powershell
pnpm install --frozen-lockfile
pnpm kernel:assemble
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
pnpm exec tsx --tsconfig tsconfig.runtime.json --test tests/e2e/backup-workflow.test.ts
```

在当前平台打包后，将`WEFTPILOT_PACKAGED_EXE`设为实际EXE路径，再运行上面专项及`pnpm test:e2e`。
默认专项使用新建的合成Git仓库和独立userData，只替换系统文件选择对话框；SQLite、加密、内核工具进程和真实位置切换均不替换，不调用模型。
不要对已有失败现场使用覆盖打包或清理命令。
