## 离线打包与网络边界

标准packager下载锁定Electron42时HTTPS握手失败，原失败输出保留。当前系统缓存存在完整官方`electron-v42.0.0-win32-x64.zip`，通过GitHub连接器读取[官方发行元数据](https://github.com/electron/electron/releases/tag/v42.0.0)，实测144296793bytes、SHA-256 `2707fbf25e0e18211a00f90b97e0fb2a00cf10a17ef0fa9d873e177e1d3286bc`与官方asset digest一致。使用锁定packager19.0.3官方`electronZipDir`选项在新目录离线装配，不重制运行时、不跳过证书验证或改变生产构建策略。新包内131文件逐项摘要、精确集合和内外两份lock一致；普通packager额外artifact-lock仅作为锁内容核对，不放宽安装器严格文件集合规则。

复现离线装配时，先核验官方归档的版本、目标平台、大小和摘要，再向`@electron/packager`传入同一标准构建参数及本机已核验缓存目录作为`electronZipDir`，使用全新out路径。正常联网仍按README执行`pnpm package`；CI/新设备的Git获取与Electron下载在网络恢复前不宣称通过。本机CI专用内核只读凭据保持既有权限，当前问题属于本机传输及备用连接器上传权限，不能以此扩大CI token权限。

范围差异明确保留：项目默认团队/描述的内核字段与配置、项目列表至任务管理的项目筛选跳转、复制Git地址等尚未接入，不伪造原型演示团队/描述或仓库状态，也不将本增量当整体原型封板。远端CI、macOS用户设备、飞书角色路由、签名和公开发行待办沿用现有清单。

复现验证：按README装配固定内核并执行严格检查；`pnpm --dir .kernel/source test`验证锁定源码。构建全新实际包，指定`WEFTPILOT_PACKAGED_EXE`后执行`pnpm test:e2e`，定向`pnpm exec tsx --tsconfig tsconfig.runtime.json --test tests/e2e/project-catalog.test.ts`。跨设备首先需正常推送本机两仓提交，远端分发/CI结果另记，不把本机实际运行扩写为原生Mac验收。
